## Soft Glass 改版与性能修复（2026-09-28，v0.5.0）

触发：用户反馈两点——① 加了 Glass 之后不如之前流畅；② 玻璃观感与参考图（UWORK 一类
"近白面板 + 柔和光影 + 大留白"）差距大，装饰过多。用户要求把方法固化成 skill。

### 性能：先定位再改

同一份页面（1600×1000，Chromium）用浏览器内探针实测，改版前：

| 场景 | p50 | >32ms 帧数 |
| --- | --- | --- |
| 只滚动 | 8.7ms | 0 / 135 |
| 滚动 + 指针移动 | **32.8ms** | **73 / 135** |
| 静止 + 指针移动 | 25.4ms | 16 / 85 |

只滚动是快的，一动指针就崩 → 瓶颈不是玻璃本身，而是**跟随指针的高光**：
每帧给 `:root` 写 CSS 变量，高光层用 `background-attachment: fixed`
（背景绘制依赖滚动位置、无法合成，变量一变就大范围重绘）。

逐项 A/B（360 张卡片、同一 DOM、交错多轮）确认每个结论：

| 变体 | p50 |
| --- | --- |
| 基线 | 23.0 / 22.5ms |
| 瀑布流条目 `will-change: transform` | **8.1 / 8.1ms** |
| 只提升图片容器 `.card-media` | 21.2 / 21.1ms（无效） |
| `contain: layout paint style` | 6.7 / 33.6 / 21.6ms（不可复现，单次采样不可信） |
| `content-visibility: auto` | 12.5 / 12.4ms |
| 关掉主面板 `backdrop-filter` | 23.5ms（**无帮助**，证明"玻璃=卡"是误判） |

改动：删除指针跟随高光与 `background-attachment: fixed`；背景层去掉 `filter: blur(48/56px)`
改画 `radial-gradient` + 极慢 `translate3d`；`backdrop-filter` 从 242 处收敛到 2 处
（弹层打开时 4 处，含遮罩），半径 28px → 18px；恢复瀑布流条目的 `will-change: transform`；
用 CSS 胶囊替换 liquid-glass-react（其 SVG 位移滤镜会在 `mousemove` 里重建并触发重渲染），
依赖一并移除，产物 318KB → 264KB。

改版后（240 张卡片、`mode:'both'`）：

| 场景 | p50 | p90 | 最大 | >32ms |
| --- | --- | --- | --- | --- |
| 亮色 滚动 + 指针 | 4.2ms | 4.7ms | 9.0ms | 0 |
| 暗色 滚动 + 指针 | 4.2ms | 14.9ms | 29.0ms | 0 |
| 360 张卡片 滚动 + 指针 | 9.1ms | 11.6ms | 22.1ms | 0 |

## 收藏库解析修复（2026-09-28，v0.5.1）

触发：用户报告「我的宝贝 / 无辨色」详情内页图片全部不显示（缩略图正常）。排查后发现是
 treasures 库的一组解析问题，共修四类，并顺带修了用户指出的 MOC 笔记分类与标题问题。

### 1) 正文图片不显示（根因：文件名带空格）

`![[Pasted image 20260426145213.png]]` 这类嵌入被改写成 markdown 图片
`![图](media://Pasted image ….png)`——**媒体 id 里有空格**，marked 把链接目标在空格处截断，
后续 `media://` 回查查不到，图片被整体丢弃；而缩略图走的是 `cover.url`（不经 markdown），
所以"缩略图正常、内页全空"，与用户观察一致。修复：媒体 id 写入 markdown 时按
`encodeURIComponent`（外加 `!'()*`）编码，`renderBody` 回查时解码。同样修复了 md 语法
`![图](Attachments/image 1.png)` 目标带空格时直接不匹配的问题（原正则 `[^)\s]+` 在空格截断）。
此前 parse.test.ts 的「中文与空格文件名」用例只断言"登记了媒体"，没断言"渲染出 <img>"，
所以一直没抓到——已补断言。附带收益：重名后缀 `#2`（`#` 不编码会被当 fragment）与
文件名含括号的情况一并修复。

### 2) 封面路径解析基准不全

frontmatter 的 `封面图: 我的收藏-书法/Attachments/xxx/….jpg` 是**相对收藏库根**的路径，
而 `resolveLocal` 只试「笔记目录」与「vault 根」两个基准 → 318 篇里 301 篇解析失败，
静默回退到"正文第一张图"（所以看起来正常，其实大多不是用户指定的封面）。
修复：解析基准改为「笔记目录 → 笔记父目录 → 收藏库根 → vault 根」逐级尝试。
另：同一文件被正文和封面重复引用时复用同一条媒体（消除 `xxx.png#2` 冗余条目）；
HEIC/HEIF/TIFF 浏览器无法显示，不再选作封面（改用正文首图，正文里保留原文并给加载失败提示）；
`/api/media` 补 `.svg` 的 MIME（39 篇的统一占位封面是 SVG，此前按二进制下发导致 `<img>` 不渲染），
并对 SVG 响应加 `Content-Security-Policy: sandbox` 禁脚本。

### 索引失效机制（本次新加）

## 全项目深度审查与修复（2026-09-28，v0.6.0）

方式：逐行读完全部源码（服务端 / 前端 / 脚本，约 8900 行）+ 三路并行审查（样式死代码、部署脚本与
文档一致性、测试覆盖缺口）。每条结论都先用真实 vault 数据或代码核实，修复后**回退旧代码验证新测试
确实失败**，再跑全量回归。发现的问题分「真实影响用户」与「潜在/工具链」两类，全部落地。

### 真实影响用户（按影响排序）

1. **938 张封面里 293 张读不到尺寸，被强行按 4:3 裁切**。`server/reader/webp-size.ts` 只解析 WebP，
   而 2375 个 jpg / 391 个 png 媒体全部拿不到宽高。改为按**文件头**解析 WebP/PNG/GIF/JPEG
   （`server/reader/image-size.ts`），并支持无扩展名文件。修复后：解析审计 938 张封面 **0 张缺尺寸**。
2. **无扩展名图片以 `application/octet-stream` 下发**（藏品库里有 37 个名为 `640` 的无扩展名图片）。
   媒体路由现按文件头嗅探 MIME，并补齐音频类型（`.m4a/.mp3/.wav/.ogg/.aac`，此前日记音频只能下载）。
   实测：`/api/media/<宝贝>/640` → `Content-Type: image/webp`。
3. **3 个"破图"文件其实是下载失败时存下的 500 JSON 响应**（`{"code":500,"msg":"服务器异常…"}`）。
   现在解析时判定 `displayable=false`：不选作封面，并在 `parse-audit` 里列出来（用户可去修那几篇笔记）。
4. **扫描完整性三处缺陷**：
   - 「有意跳过」的笔记诊断写着"已从库中移除"，实际会被扫描尾部的 missing 兜底重新加回（行为与诊断不符）；
   - ID 冲突时同一路径会被推入两条记录（一条 available 一条 missing），`total` 多算、`detail` 指向 missing 副本；
   - 快路径（mtime/size 未变）不登记 ID，导致撞 ID 的文件在**第二轮刷新**被当成首个占用者收进索引。
   三处都已修，并用"回退旧代码 → 新用例失败"验证。
5. **「零可用笔记」保护从不生效**：判据是 `records.length === 0`，而消失的文件会以 missing 保留，
   该条件永远不成立。改为看 available 计数：一篇都读不到而旧库非空时给出醒目诊断
   （**不**硬失败——硬失败会让"确实清空库"的用户没有出路；记录与分类始终保留）。
6. **AI 兜底没有调用上限**：分类表被重置（删 categories.json）或一次导入几百篇时会串行打几百次接口。
   新增 `AI_CLASSIFY_MAX_PER_REFRESH`（默认 40），超出的留待下次刷新并在诊断里说明。
   顺带修掉 `AI_CLASSIFY_TIMEOUT_MS` 写错（NaN）时会"立即超时"从而静默关闭 AI 的问题。
7. **首扫的自动分类结果只进服务端日志、不进页面诊断**（`job` 为空时消息丢失），现在会写进索引诊断。
8. **静态缓存把 `index.html` 也缓存 1 小时**：部署完浏览器可能仍拿旧壳（"部署了但没变化"）。现按
   Vite 的 assets 目录判定——`index.html` 为 `no-cache`，`/assets/*` 为一年 immutable。
   注：第一版按"哈希长度 ≥8"猜，实测该构建的哈希是 7 位，被自己的测试头打回，已改为按目录判定。
9. **自定义时间范围的预填用浏览器本地日期**，与全站 Asia/Shanghai 口径不一致（设备不在东八区会差一天）。
   改为 `shanghaiDateDaysAgo()`。
10. **`categories.json` 里 `initialAssignments: null` 会通过校验后崩溃**（`typeof null === 'object'`）。
    校验改为非空对象判定，损坏文件按损坏处理并出诊断。

## 工具栏与内容的分界（2026-09-28，v0.6.3）

用户三轮反馈才收敛，最终形态是「5px 空隙 + 1px 分界线 + 12px 渐隐投影」：

1. "筛选行下面完全没有间隔，让人很难受" → 我先加留白（头部下内边距 26px、结果区 8px，静止 34px）。
2. 被否："间距又搞得太大了…我只需要一条边缘有质感的线，下面带点阴影，让人感觉是两层空间。"
   → 改为「线 + 投影」，但把间距收到 12px 且**误解了位置**（我以为说的是线下方，其实说的是线上方）。
3. 澄清："我说的是这个筛选器和阴影线之间的空隙" → 线上方留空隙；我先给 3px，用户改为 **5px**。

**最终实现**（`src/styles/app.css`）：
- `.main-header { padding: ... 5px }` —— 筛选行到分界线的空隙（线上方 5px 干净面板底色）
- `.main-header::after` —— 挂在头部块下缘、撑满面板宽度：`border-top: 1px solid var(--edge-line)`
  ＋ `background: linear-gradient(to bottom, var(--edge-shadow), transparent)`、高 12px
- `.results { padding-top: 12px }` —— 正好容纳投影的渐隐带，内容不被压住
- `pointer-events: none`（实测 `elementFromPoint` 仍命中卡片）；`z-index: 3` 高于表格粘性表头的 2

过程中删掉的两处自作主张：① 曾加过 1px "上缘受光"亮边（`--edge-rim`），它占掉用户指定的空隙，
且暗色下与分界线连成 2px 亮带 → 删除；② 曾把线下方间距改成 2px 让内容紧贴（误解需求）→ 还原 12px。

**实测几何（截图逐像素剖面，暗色 x=300）**：
`y257..260` 纯面板底色（= 5px 空隙）→ `y261` 分界线（+7）→ `y262..272` 投影由 −10 渐隐到 0 →
`y273` 起为卡片内容。亮色同构（分界线为 −11 的暗线）。DOM 实测 `筛选行→线 = 5px`、`线→内容 = 12px`
（636×520 与 760×560 一致，筛选行换行时同值）。

## 表格标注列 + 批量归档（2026-09-28，v0.7.6）

### 写测试时发现的一个真实缺陷（已修）

`corpus.jsonl` 里每条都带 `starred` / `status`，而 `contentHash` **有意不含**这两项
（为的是"归档一篇不该让外部 embedding 重算"）。第一版把**跳过写入**也建立在 `contentHash`
派生出来的 `contentDigest` 上——于是**"只归档 / 只标星"会被判成"内容没变"，文件不重写，
`corpus.jsonl` 里的状态就停在旧值**，`manifest.json` 里的 counts 也跟着撒谎。

补两条用例先复现（都是 `expected false to be true`：跳过写入本该发生却没发生），再修：
manifest 增加 `digest`（整条记录的摘要）作为"要不要重写"的判据，`contentDigest` 归位为
**只给外部管道做增量**；同时把 `appVersion` 纳入重写条件（否则升级后导出物一直写着旧版本号）；
`revision` 明确**不进**条件（每次扫描都 +1，拿它判断等于每次刷新重写几 MB）。
两条用例现在同时断言两侧：文件重写了、状态是新的，而 `contentDigest` **不变**。

## OCR 加进度反馈（2026-09-28，v0.9.1）——用户报"点了没反应"

**先查证据，再回答**：服务端日志与存储都没有撒谎的空间——
`OCR 完成: 6a9e8a920000000012035d7f 识别 8 张（缓存 0 张）`，时间跨度 13:50:16 → 13:51:03。
**它确实跑了，而且成功了**。用户点的是「🟡MIT Media Lab 27Fall 20组开放申请」那篇（**13 张图**），

（用户随后又点了一次，两次合起来把 13 张都跑完了。）

### 修法：把"一次闷 47 秒"改成"逐张请求 + 实时进度"

- **前端逐张调**（每张一个 `POST /ocr {mediaId}`），不再是一次调用处理整批：
  - 面板在**识别过程中就渲染**（原来只在有结果或有消息时才出现，所以运行期间界面上什么都没有）；
  - 头部显示「识别中 2/8…」（`font-variant-numeric: tabular-nums` 防跳动）+ 一条 3px 进度条
    （宽度按完成比例，260ms 过渡），面板 `aria-busy=true`；
  - **每张完成立即出现**在面板里，不等最后一次性冒出来；
  - 开始与结束各给一条 toast（复用「刷新收藏库」那套 `showToast`）：
    「开始识别 N 张图…（每张约 5–10 秒，可以继续看页面）」/「识别完成：N 张 · 还有 M 张没识别…」。
- 分批上限仍在（前后端都是 8）：一次点击不会替用户烧掉 13 张；剩下用「识别其余 N 张」显式再点。
  全部识别完后按钮文案变「重新识别」。
- 逐张请求还有个附带好处：单次请求最长只有 ~10 秒，不会因为一篇 13 张图而挂一个几十秒的请求。

**顺带修掉一个语义 bug（新用例抓到的）**：`remaining` 原来按"本次请求的目标数"算，
指定 `mediaId` 时恒为 0；而它的用途是界面上的「识别其余 N 张」。改成**处理完后再按这篇笔记整体数**，
语义写进 `shared/types.ts` 的字段注释。

### 实测（真实调用）

| 场景 | 证据 |
| --- | --- |
| 识别 **3 张**的笔记（书法 125 汉字频次表，文字全在图里） | 点击后 **1.2 秒内**出现「识别中 1/3…」+ 进度条 0%；采样到「识别中 3/3…」时**面板里已经有 2 条结果**（逐张出现，不是最后才冒）；结束时进度条消失、`aria-busy=false`、文案「识别完成：3 张」 |

**测试：198 → 199**（新增 1 条「指定 mediaId 时只识别那一张」——界面现在每张图都走这条路，

凡是**用户点一下要等十秒以上**的动作，必须当场给出可见的进度——否则做得再对也等于没做。

## 识别文本面板重做（2026-09-28，v0.9.2）——用户三条反馈

用户截图反馈（那篇 13 张图的 MIT 笔记）：
> 「1. 它没有滚动条 2. 它也不能收缩起来 3. 我也不知道它对应的是什么图，就这样展示出来，直接影响了整个页面的浏览」

三条都成立，而且都指向同一个根因：**第一版把识别结果做成了压在正文上方的常驻面板**——
`.detail-panel` 是 flex 列，面板 `flex:none` 且默认全展开，9 条文本把正文挤到屏幕外；
每条内部是 `max-height + overflow-y:auto`（滚动条在滚动时才现形，用户看不到，等于"内容被无声截断"）；
标签只写「图 1/图 2」，而这两张图在截图里长得几乎一样。

### 重做后的形态

| 原来的问题 | 现在 |
| --- | --- |
| 压在正文上方、默认全展开，把正文顶出屏幕 | **挪进正文流**（`.detail-article` 之前），**默认折叠**：折叠时只有一行（实测 46-48px）「▾ 图片文字 13 张」 |
| 内滚动条（看不到、也不说明有多少内容） | **完全不用内滚动条**（实测 `innerScrollables: 0`）：折叠时 `max-height: 6.4em` + 渐隐遮罩（`mask-image`），下面挂「展开全部（19 行）」把"还有多少"直接写出来；展开后完整显示 |
| 「图 1/图 2」认不出是哪张 | **每条左边一个 64×64 缩略图**（取自 `/api/media/...`，懒加载），点击在新标签打开原图；鼠标悬停有提示 |

结构：`section.ocr-section` → 头部一行（折叠按钮 + 张数 + 识别中进度 / 「识别其余 N 张」）→
进度条 → 每条 `[缩略图] [图 N · 复制 · 重来] [文字]`。
识别**过程中**面板自动展开（`setOcrOpen(true)`），跑完留在展开态；下次进来仍是折叠的。

### 实测（1440×900，明暗两主题，13 张图那篇）

- **折叠**：`aria-expanded=false`、高度 46px、DOM 里 0 条 → 点一下展开为 13 条。
- **无内滚动条**：`[...document.querySelectorAll('.ocr-section *')].filter(overflowY 是 auto/scroll 且 scrollHeight>clientHeight)` = **0**。
- **缩略图**：13 个 `.ocr-thumb`，CSS 尺寸 64×64、`naturalWidth` 来自 1080×1440 原图、加载成功。
- **折叠态文本**：`clientHeight 83 / scrollHeight 677`、`overflow-y: hidden`、`mask-image` 命中 —— 靠渐隐 + 「展开全部（N 行）」说明，而不是让人去猜有没有更多。
- **对比度**（含半透明背景逐层合成，两种主题）：标题 6.77 / 8.62；「N 张」徽章 6.24 / 8.99；
  「图 N」4.54 / 5.65；正文 14.47 / 16.38；「展开全部」6.77 / 8.62；底部提示 4.54 / 5.65 —— 全部 ≥ 4.5。
- `__uiLayout()`：`overflowing: []`、`cardOverlaps: []`；`__uiAudit()` 零失败。
- 截图：`docs/screenshots/ocr-section-light.png`、`ocr-section-dark.png`。

### 这次的设计教训（值得留在文档里）

**附加内容不要"默认敞开地压在正文上方"。** 识别文本是附加信息，它的正确位置是
正文流里的一个**默认折叠**的板块；**有没有更多内容要让用户一眼看出来**（渐隐 + 行数），
不要指望一个只有滚动时才出现的滚动条；**"图 1/图 2"这类序号不是身份**，要给缩略图。

## 修：短文本的最后一行被渐隐吞掉（2026-09-28，v0.9.3）

用户截图（乔布斯演讲海报那篇，识别出来正好 4 行）：「最后一排识别的字被隐掉了」——
`12 Jun 2005` 半透明地糊在那里。

**根因是两个判断不一致**：我给「要不要折叠」用的是 JS 数换行（`lines > 4`），
而裁切与渐隐是 **CSS 无条件施加**的（`.ocr-text:not(.expanded) { max-height: 6.4em; mask-image: ... }`）。
于是 4 行文本（≈87px）落在 6.4em（≈83px）之外被裁、被渐隐，却又因为"换行数不够 5"没有展开按钮——
**最后一行永久看不见**。更长的问题：`mask-image` 加在整块上，**任何长度的文本**都会朝底部褪色，
短文本也被渐隐。

**改法**：不再数行，改成**测量真实溢出**，且只在真溢出时才施加裁切与渐隐。

- 新增 `OcrText` 组件：`useLayoutEffect` 里用 `scrollHeight` 与「阈值 em × 当前 font-size」比较
  （`scrollHeight` 不受 `max-height` 影响，裁切前后都返回完整内容高度，所以换宽度重排后重新量一次即可）；
  另外监听 `window.resize` 重测。
- CSS 从 `.ocr-text:not(.expanded)` 改成 **`.ocr-text.clamped`**——只有量出溢出的那一条才有裁切 + 渐隐。
- 展开按钮的出现条件与裁切条件现在是**同一个变量**，不可能再出现"被裁了却没有展开入口"。
- 阈值从约 3.8 行放宽到 `9em`（约 5 行）：4 行的海报、2 行的短句本来就该完整显示。

### 实测（浏览器，正是用户报的那两篇）

| 案例 | 结果 |
| --- | --- |
| 乔布斯海报（**4 行**） | `clamped=false`、`clientHeight 87 = scrollHeight 87`、`mask` 无、**无展开按钮**；四行完整（`12 Jun 2005` 清晰可见） |
| 课程表（**47 行**） | 折叠：`clamped=true`、117px 可见 / 1048px 内容、渐隐生效、按钮「展开全部（47 行）」；展开后 `clientHeight 1048 = scrollHeight 1048`、渐隐关闭、按钮变「收起」 |
| 布局 | `__uiLayout()`：`overflowing: []`、`cardOverlaps: []` |

截图：`docs/screenshots/ocr-short-text-fixed.png`。

**教训（已在 `plan.md` §18.2 与 skill 反馈里记下）**：**折叠的判断条件与折叠的实现必须是同一个来源**。
"用 A 决定要不要折叠、用 B 真的折叠"这种写法，迟早会出现"A 说不折、B 却折了"的静默隐藏；
凡是"看起来只是一行 CSS"的隐藏，都要用**测量**而不是**估算**（数 `\n` ≠ 视觉行数）。

## 第三轮深度审查（2026-09-28，v0.10.0）

用户要求："先全部都 deep review 一遍，然后再做下一步语音转录"。前两轮（v0.6.0 / v0.6.1）审的是当时已有的代码；
这轮的重点是 **v0.7–v0.9 新写的那批（标注层 / 语料导出 / OCR）从未被深审过**。

**方法**：五路并行审查（服务端核心 / v0.7–v0.9 新功能 / 前端 / 测试与脚本 / 文档与安全），
**每条结论我都自己复核过**——只有复核确认的才动手改。复核时又实测复现了本轮最严重的两条
（并发写丢更新、分类非幂等），没有采信"可能是这样"的推断。

### 一、会丢数据 / 会花钱（最高优先级）

1. **并发写标注或分类会静默丢更新 — 已复现并修复。**
   `AnnotationsService.patch` 与 `CategoriesService.setOverride` 把"检查 revision → 合并 → 写盘 → 换内存"
   跨在 `await` 两端；`JsonStore` 只保证磁盘写入有序，管不住这个读-改-写序列。实测：
   ```js
   await Promise.all([ann.patch('noteA', {star:true}, 0), ann.patch('noteB', {star:true}, 0)])
   // 修复前：两条响应都报 revision 1，实际只存下 1 条，noteA 的标星没了
   ```
   分类同样（并发给两篇设不同分类 → 只落盘一条）。
   **修法**：给两个 store 各加一条写队列，把整段读-改-写串起来。**语义变化要说清楚**：
   两条请求都拿着同一个旧 revision 时，现在后到的那条会**如实返回 409 冲突**（原来"两边都成功却丢一条"）。
   这才是乐观并发该有的样子——数据不再静默丢失。回归用例见 `tests/review-fixes.test.ts`。

2. **`setOverride` 不幂等 — 已修。** 重复写同一个分类值也会写盘并抬 `revision`（实测 1 → 2），
   而详情里的分类菜单点"当前已选"就会触发；白写一次还会让另一个已读到旧 revision 的标签页莫名撞 409。
   现在只在**覆盖值真的变了**时才写（把 seed 分来的分类显式钉成覆盖仍算真实改动）。

3. **识别文本先改内存、再写盘 — 已修。** `put/remove/removeRef` 原来是"先 push/delete 内存，再 await save"。
   写盘失败（磁盘满 / NAS 掉线）时内存留着盘上没有的结果，而且因为 `get()` 已经能查到它，
   同一个 ref 之后会被判成"已有、无需再写"，**永远不再重试**——正是"内存说成功、盘上没有"。
   现在先在副本上改、写盘成功后才换内存；回归用例用"把目标文件路径占成目录"来制造写失败。

4. **测试可能真的调用 AI 供应商（花用户的钱）— 已堵。**
   `aiClassifyConfigFromEnv()` 直接读 `process.env.AI_CLASSIFY_API_KEY`；按文档做法在本地导出过
   `deploy/production/.env` 的开发者，跑 `npm test` 时刷新流程会真的发请求，而 corpus/annotations/library/http
   这些集成测试全都会走到。现在：`tests/setup.ts`（vitest `setupFiles`）**清掉所有 `AI_*`/`MIMO_*` 环境变量**，
   并且把指向 AI 网关的真实请求变成"抛错"而不是"静默花钱"；
   `tests/safety-net.test.ts` 专门验证这道防护本身（含"非 AI 地址照常放行"）。

5. **关掉详情后 OCR 仍在后台继续跑 — 已修。** 识别是逐张、可能持续一分钟的付费长任务，
   原来的循环没有"组件是否还挂着"的判断。**实测证据**：那篇 6 张图的笔记，点识别后 1.3 秒关掉详情，
   修复后前端只发出 **1 个** `/ocr` 请求（在途的那一个），修复前会继续发到 6 个。

### 二、结果不正确 / 界面对用户说谎

6. **索引指纹漏了内容源 — 已修。** `indexSig` 只含收藏库结构 + 解析器版本。
   同一份 `DATA_DIR` 换了 `SOURCE_ROOT`（搬家 / 换盘 / 开发切生产）时签名不变 → 继续用旧库的索引：
   列表看着正常、媒体全 404、且没有任何提示。现在 `vaultRoot`（与 collection `type`）都进指纹，
   实测"同一 dataDir 指向另一 vault → 自动重建、能查到新库的笔记"。

7. **OCR 用 mediaId 判"是否已识别" → 图片被换掉后永远用旧文本 — 已修。**
   内容 hash 缓存根本没被问到。现在每张都读盘算 hash：hash 命中就复用（不花钱），否则才调模型；
   **上限只约束真正调用模型的张数**（命中缓存的不占名额）。回归用例：同名图片换成不同字节 → 会重新识别，
   且旧结果被摘掉（否则同一个 mediaId 挂两条，界面会出现两个「图 1」）。

8. **孤儿引用让数字说谎 — 已修。** 笔记换掉/删掉附件后，旧的 ref 还挂着：
   `mediaText.length` 虚高会把「识别其余 N 张」按钮顶掉、缩略图 404、文本还继续参与搜索与语料。
   现在刷新管道里调一次 `pruneRefs`（一次读 + 至多一次写）。

9. **语料导出的"要不要重写"漏了目录排版的依赖 — 已修。** `catalog.md` 的小节顺序/标题来自
   `collections`（改分类顺序、改分类名都不动任何一条记录），解析器版本还写在目录头部。
   只比记录摘要时，"重排了分类顺序"之后目录会永远停在旧顺序。现在判据里加了 `metaDigest`。

10. **"数字与列表打架"（两处）— 已修，浏览器实测。**
    ① 切换作用域（标星 / 归档 / 分类 / 时间范围）时不清列表：标题与侧栏立刻变成新口径（"标星 1 篇"），
    网格里还挂着上一批 120 张卡片。现在**在 `patchQuery` 里统一判断"作用域是否变了"**（分类/标星/状态/时间范围/时间口径）
    并清空列表进入加载态；搜索词与排序不清（那是"同一批里再筛/再排"）。
    ② 反向操作补不回列表：在「只看标星」里取消标星会把这条移出列表，再标回来时只 `map` 现存行 → 补不回来。
    分类同理。现在这两条路径在筛选生效时改为重新取数。

11. **表格行的键盘事件会吞掉子控件 — 已修。** `<tr>` 的 `onKeyDown` 没有判断事件来源，
    空格/回车从勾选框、星标、归档按钮冒泡上来会**顺手打开详情**。
    浏览器实测（真实按键）：焦点在勾选框上按空格 → 勾选成功、**详情不打开**；按回车同样不打开。

12. **详情状态会跨笔记 — 已修。** 组件没有 key，从"焦点跑到后面卡片"这条路径切换笔记时 React 复用同一实例，
    上一篇的"展开了哪些图/备注面板是否开着/识别到第几张"会带进下一篇。现在 `<DetailDialog key={note.id}>`。
    实测：A 篇展开识别文本 → 关闭 → 打开 B 篇 → **是折叠的**。

13. **标签目录缺请求时序防护 — 已修。** 快速切库时两次 `api.tags()` 可能乱序返回，
    后到的旧响应会覆盖新库的标签（列表那边早就有 `seqRef`，标签没有）。现在加上同样的序号判断。

14. **顶层分类计数不用工作集口径 — 已修。** 归档一篇之后 `libraryInfo()` 的顶层 `uncategorized`/分类计数不动，
    而 `collections` 里的动 —— 同一页上两套数字。现在顶层也走 `inWorkSet()`。

15. **索引里全是 missing 时启动不自愈 — 已修。** 上一轮如果内容源没挂上，记录会全部留成 missing，
    `notes.length !== 0` 于是启动不重扫；修好挂载后重启仍是空库。现在"一篇可读都没有"也会自动重扫。

16. **解析错误被同时计入 `errors` 与 `skipped` — 已修。** `skipped` 的语义是"有意跳过"（索引页/空笔记），
    两处都加会让刷新诊断的两个数字都失真。

17. **vault 边界守卫只覆盖导出目录 — 已扩到全部写入目录 + realpath。**
    原来只有 `EXPORT_DIR` 有硬断言，而 `DATA_DIR`/`BACKUP_DIR`/`LOG_DIR` 配错照样会往 Obsidian 里写
    （`overrides.json`/`annotations.json`/`media-text.json`/备份/日志）。现在抽成
    `server/storage/vault-guard.ts`，**启动时四个目录全部校验、配错就拒绝启动**；
    并且先做词法比较再做一次 realpath 比较（软链接/junction 也能拦住）。回归用例含"用 junction 指向 vault"。

18. **语料导出没有串行化 — 已修。** 手动点「导出语料」可能正好撞上刷新后的自动导出；
    临时文件名同进程同毫秒会相同、manifest 的读-改-写也会互相覆盖。现在走一条写队列。

## 语音转录 ASR（2026-09-29 凌晨，v0.11.0）

### 实现
